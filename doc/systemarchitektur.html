Architekturübersicht

Diese Dokumentation beschreibt die Systemarchitektur der 360° Drehteller Steuerungsanwendung. Sie umfasst die Hauptkomponenten, deren Zusammenspiel und den Datenfluss innerhalb des Systems.

|                     |    |                        |    |                      |
|  Webanwendung       |    |  Anwendungslogik       |    |  Hardware-Steuerung  |
|  (Flask Blueprints) |<-->|  (Controller & Utils)  |<-->|  (Arduino & Kamera)  |
|                     |    |                        |    |                      |
+---------------------+    +------------------------+    +----------------------+
            ^                           ^
            |                           |
            v                           v
+---------------------+    +------------------------+
|                     |    |                        |
|  Dateisystem        |    |  Konfiguration         |
|  (Projekte & Fotos) |    |  (config.json)         |

+---------------------+    +------------------------+

Hauptkomponenten

1. Webanwendung (Flask)

Die Benutzeroberfläche der Anwendung ist als Flask-Webanwendung implementiert und in verschiedene Blueprints aufgeteilt:

  • main_bp: Hauptseiten und grundlegende Funktionalität
  • api_bp: REST-API-Endpunkte
  • settings_bp: Einstellungsverwaltung
  • projects_bp: Projektverwaltung
  • viewer_bp: 360° Viewer

Die Blueprints werden in der register_blueprints() Funktion in app/__init__.py registriert und bilden die Struktur der Webanwendung.

2. Controller

Die Controller sind für die Steuerung der Hardware zuständig und bilden die Brücke zwischen Webanwendung und Hardware:

  • ArduinoController: Kommunikation mit dem Arduino über serielle Schnittstelle
  • CameraController: Steuerung von Webcams und/oder gphoto2-kompatiblen Kameras
  • TurntableController: Drehteller-Steuerung (nutzt den ArduinoController)

Diese Controller werden in der initialize_controllers() Funktion in app/__init__.py initialisiert und sind als globale Variablen verfügbar.

3. Utilities

Die Utility-Klassen bieten gemeinsam genutzte Funktionalität für das gesamte Projekt:

  • ConfigManager: Verwaltung der Konfigurationseinstellungen
  • PathManager: Verwaltung von Dateisystempfaden
  • DeviceDetector: Erkennung von angeschlossenen Geräten
  • ViewerGenerator: Generierung von 360° Viewer-HTML

4. Models

Die Modelle repräsentieren die Datenstrukturen der Anwendung:

  • Project: Repräsentiert ein Fotoprojekt
  • PhotoSession: Repräsentiert eine Fotosession innerhalb eines Projekts

Datenfluss

1. Startsequenz

  1. run.py parst Kommandozeilenargumente und erstellt die App-Instanz
  2. create_app() initialisiert die Anwendung, erstellt Verzeichnisse und initialisiert Controller
  3. Die Blueprints werden registriert und die Anwendung gestartet
run.py ─→ parse_arguments()
  ↓
create_app() ─→ create_directories() ─→ initialize_controllers() ─→ configure_logging() ─→ register_blueprints()

2. Projektbasierte Funktionen

Der Workflow für projektbasierte Funktionen:

  1. Benutzer erstellt ein Projekt in der Weboberfläche (Formular auf /projects/new)
  2. Der Projektcontroller speichert die Projektdetails
  3. Im Hauptbereich kann der Benutzer den Drehteller steuern und Fotos aufnehmen
  4. Die Fotos werden im Projektverzeichnis gespeichert
  5. Der Benutzer kann eine 360°-Ansicht generieren, die im Viewer angezeigt werden kann
Web UI (Projekt erstellen) ─→ ProjectsController ─→ Dateisystem (Projektverzeichnis)
               ↓
Web UI (Drehteller steuern) ─→ TurntableController ─→ ArduinoController ─→ Hardware
               ↓
Web UI (Foto aufnehmen) ─→ CameraController ─→ Hardware
               ↓
Web UI (360° generieren) ─→ ViewerGenerator ─→ 360° HTML/JS Viewer

3. Konfigurationsmanagement

Der Workflow für die Konfigurationsverwaltung:

  1. Die Konfiguration wird beim Start aus config.json geladen
  2. Der Benutzer kann Einstellungen in der Web-UI ändern
  3. Die Änderungen werden in config.json gespeichert
  4. Die Controller nutzen die Konfigurationswerte für ihre Operationen
config.json ─→ ConfigManager (laden) ─→ Controller nutzen Konfiguration
   ↑
Web UI (Einstellungen) ─→ ConfigManager (speichern)

Funktionsfluss bei einer Fotosession

Beispiel: 360° Fotosession

Eine typische 360° Fotosession läuft wie folgt ab:

  1. Benutzer wählt ein Projekt aus und startet die Fotosession
  2. Der Drehteller wird auf Position 0° zurückgesetzt
  3. Für jeden Schritt (abhängig vom konfigurierten Winkelschritt):
    • Ein Foto wird mit der Kamera aufgenommen
    • Das Foto wird im Projekt-Session-Verzeichnis gespeichert
    • Der Drehteller wird um den konfigurierten Winkelschritt gedreht
  4. Nach Abschluss kann der Benutzer einen 360° Viewer generieren
Web UI (Session starten) ─→ TurntableController.start_session()
                                          ↓
                            TurntableController.reset_position()
                                          ↓
                   ┌────────────── Für jeden Schritt ──────────────┐
                   ↓                       ↓                       ↓
CameraController.capture_photo() ─→ Foto speichern ─→ TurntableController.move_degrees()
                                          ↓
                            ViewerGenerator.generate_viewer()

Zusammenfassung

Die 360° Drehteller Steuerung folgt einer klaren Architektur mit einer Trennung von:

  • Präsentation: Webanwendung mit Flask-Blueprints
  • Geschäftslogik: Controller und Utilities
  • Datenhaltung: Projekte, Fotos und Konfiguration
  • Hardware-Interaktion: Arduino- und Kamera-Steuerung

Diese Aufteilung ermöglicht eine gute Wartbarkeit und Erweiterbarkeit des Projekts. Fast alle definierten Funktionen werden aktiv genutzt, und die Kommunikation zwischen den Komponenten erfolgt über klar definierte Schnittstellen.
